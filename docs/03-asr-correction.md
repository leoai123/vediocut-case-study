# 03 · ASR 校正：用世界知識，不建詞表

## 問題

本地 ASR 對一般口語相當準，錯誤高度集中在**專有名詞的同音誤聽**：店名、路名、品牌、
地標、菜名。口音特徵會放大這個問題——前後鼻音不分、捲舌音弱化，都讓同音候選暴增。

這些錯字不能放著：它們會直接出現在字幕上，而且往往正好是觀眾最想知道的資訊（「這家店
叫什麼？」）。

## 為什麼不建詞表

直覺解法是人工建一份「這支片會出現的專名」詞表交給模型。實測結果是**有害**：

| 設定 | 修正筆數 | 備註 |
|---|---|---|
| 小模型 + 人工詞表 | 8 | 其中一筆照著詞表**改錯** |
| 較強模型 + 零詞表 | **17** | 包含協調者原本判定「語意不明」的詞 |

改錯的那一筆最有說服力：協調者根據逐字稿裡的一個菜名，推測這是一家燒「肉」店並寫進
詞表；小模型照著詞表把 ASR 結果改成「燒肉」。同一批素材交給零詞表的模型，它從上下文
（菜名的組成、自選醬料的描述）推出正確答案是燒「臘」。

**詞表把協調者的猜測固化成下游的權威依據，讓模型不再用自己的知識。**另一次是協調者憑
印象填了一個店名，抽幀看到招牌才發現是完全不同的名字——若沒抽幀，那個錯誤會經由詞表
傳染到整支片。

詞表因此降級為「例外補丁」：只放模型與搜尋都查不出、只有使用者知道的私有詞（例如寵物
的名字）。多數專案留空。

## 兩段式 prompt，地區中性

```
第一步：從逐字稿本身推斷這支影片的
        所在地區、主題領域、詞彙圈。
        不要預設任何特定地區——文本會告訴你。

第二步：對每個語意不通的詞
        1. 確認它在上下文中確實不通
        2. 列出同音或近音候選
        3. 這些候選在「推斷出的地區與領域」中是否真實存在
        4. 有把握就替換；沒把握就保留原文並標低信心
```

**為什麼不在 prompt 裡寫地區**：寫死地區跟寫死詞表是同一類錯誤——它讓同一套流程無法
跨地區使用，而且會讓你分不清模型是真的懂、還是在照抄提示。列出可疑詞清單也一樣，等於
洩題。

**裸考驗證**：在完全不告知拍攝地點的情況下，代理自行推斷出正確的城市、行政區與街道，
依據是逐字稿內的地標互證與用語特徵，並還原了協調者原本放棄的詞。

### 每筆修正必附信心與理由
`confidence`（high / medium / low）與 `note` 是必填欄位，會寫回逐字稿。medium / low
不代表「不可信」，而是「需要在規劃階段用畫面或搜尋驗證」。

### 明文禁則（每條都來自一次事故）
- 不得刪除子句，只能替換錯字
- 環境音造成的亂碼保留原文，不得「腦補」成通順句子
- 講者自我更正時，兩句都保留

## Guardrails

套用修正前的機械性檢查：

| 檢查 | 動作 |
|---|---|
| 修正是否屬於該批次的段落 | 不符即丟棄 |
| 長度變化 > 40% | 直接丟棄 |
| 長度變化 > 2% | 警告「需人工覆核」 |
| 段數、來源 ID、時間碼、原始文字任一被動到 | 斷言失敗，整批中止 |

**2% 這道門檻是事故補丁。**曾有一筆修正把一句帶條件子句的推薦改寫成無條件推薦，整個子句
被刪掉——長度只差 18%，沒觸發 40% 的門檻。純同音替換的長度變化應該接近 0%，所以任何超過
2% 的變化都值得人看一眼。良性的例外（例如英文品牌拼字修正會變長）看過就放行。

## 代理編排

沒有 API key 時走離線三步：匯出批次檔 → 平行派多個代理各處理幾批 → 合併結果套用。

給代理的指示刻意極簡：**只給檔案路徑，與「system 欄位是你的完整規則」**。不告訴它影片
拍什麼、不指定地區、不列可疑詞。理由同上——任何提示都會污染它自己的推斷。

選模型時用較強的那一級。關鍵能力是在地專名知識，這正是小模型的弱項。

## 協調者覆核：補代理漏的，不重做代理的

代理交回結果後，協調者還要再過一輪。這一輪不是重做，而是專抓代理系統性會漏的類型：

**畫面證據推翻同音推理**
代理因為「查無對應店名，也可能就是本名」保留了 ASR 原文——這個判斷在只有文字時是合理的。
但那家店的招牌就在畫面裡，抽幀一看就知道正確的字。畫面證據的優先級高於任何同音推理。

**音韻決定性推翻名稱吸附**
代理把一個路名還原成「逐字稿別處出現過的那條路」。但同一個 ASR 在逐字稿別處已經**正確**
轉出那條路的名字（聲母為 l），在這裡卻兩次寫成聲母 h 的音——模型不會把 l 聽成 h，所以這裡
指的是另一條同音（h 開頭）的路。「別處出現過」是較弱的證據，音韻才是決定性的。
事後另一批代理在不知情的狀況下，也從「路名是否真實存在」獨立推出同一個答案。

**偵測 no-op**
代理在報告中聲稱修了某一筆，但寫進結果檔的內容跟原文一字不差。套用時被正確跳過（沒有
變化），協調者比對「報告」與「實際檔案」才發現。**代理回報完成不等於完成。**

**系統性混淆模式**
有一批代理歸納出「某一組同音字被系統性聽成同一個字」的模式，讓協調者能回頭掃整份逐字稿
找出同模式但被別的批次放過的詞。

**該放棄的就放棄**
有幾個詞所有代理與協調者都無法可靠還原。依規則保留原文、不猜。規劃階段再決定：能繞開就
繞開該時間段，而不是剪掉整段有內容的對話。
