# 02 · 剪輯方法：逐字稿優先

## 原則

**先完成完整逐字稿再決定故事；先鎖定 A-roll 語意再補 B-roll；音樂最後加，不為卡拍破壞內容。**

### Radio edit 先成立
第一版只用聲音剪。驗收標準是**把畫面關掉也聽得懂**：在哪裡、做了什麼、結果如何。
畫面若需要補，是 B-roll 的工作；畫面不是用來掩蓋敘事斷裂的。

### 選段規則
- 只能在句尾、自然停頓或話題轉換處切
- 完整句子優先，片段長度由內容決定
- 刪掉的是**真正的**重複與口誤重來（false start），不是所有停頓與口頭禪
- 「贅字和無意義的文字要剪掉」是清理指令，不是縮短指令

### 順剪鐵律
時間順序不可重排。唯一例外是片頭的精華預告（從正片抽幾句放前面，正片原位照播）。

這條規則曾被我自己繞過一次：把一段量化總評從某支素材的 90 秒處挪到同素材 153 秒處之後
當收束，理由是「同素材內重排不算違反跨素材順剪」。結果渲染器的相鄰重疊守衛把那段的起點
鉗到前一段之後，終點卻還在原位，產生負時長，ffmpeg 直接失敗。

守衛是對的，我是錯的。回頭看那段話，講者本來就是**結論先行**——先給最具體的判斷，再逐項
論證。照他的順序反而更自然。規則因此補上：**同素材內重排也不是例外。**真要重排前，先問
講者是不是本來就這樣講。

## 規劃前的檢查清單

故事規劃前逐項過，每一項都要在規劃文件裡留下處置紀錄，不能空手放過：

| 檢查項 | 在找什麼 | 處置 |
|---|---|---|
| 重複句掃描 | 相鄰重講、false start、換句重說 | 只留較完整的那次 |
| 銜接檢查 | 章節交界的橋接句；埋的伏筆是否回收 | 缺橋接就調整章節邊界 |
| 環境音污染 | 多人場所中，鄰桌對話被轉錄成旁白 | 受污染區間禁選，記錄範圍 |
| ASR 長段標籤 | 一句話被標成極長時長（後面是無語音長尾） | 選段手動收窗，不照抄時間碼 |
| 可疑詞 | 語意不通的詞 | 見下方四階處置 |

### 可疑詞的四階處置
早期規則只有一條：「語意不明就避開」。使用者回報某一版「剪得太嚴謹」，追查發現被剪掉的
四段全是**專名被聽錯、還原後完全通順**的推薦。規則因此改成四階：

1. **先試還原**——這是不是某個專名的同音誤聽？用世界知識比對
2. **抽幀或搜尋驗證**——招牌、菜單、商品標籤常常就在畫面裡
3. **語意可推斷就照播**——口語不完美但觀眾聽得懂的，不要為一個錯字剪掉整句
4. **只有真的無法還原且會誤導觀眾**才剪（多人重疊、環境音污染）

## 精華預告
片頭抽 2–3 句當預告，正片原位重播（這是設計行為，法醫驗證時不計入非設計重複）。
選句依類型而定：探店選價格衝擊或第一口反應、日常選情緒最濃或最好笑的瞬間。
**避免結論句與總結句**——那會讓觀眾覺得已經看完了。

多句預告時刻意選不同語氣（例如：一句熱情、一句強主張、一句自嘲），三句都是推薦會單調。

## 敘事模板

九種類型：美食探店、生活日常、旅遊遊記、開箱評測、商品介紹、心得分享、知識解說、
房仲帶看、場所導覽。每個模板定義：適用情境與**不適用的判準**、章節骨架、選段原則、
預告選句風格、B-roll 密度與絕不可蓋的鏡頭、該類型的常見禁忌。

### 設計決策
- **白名單淺層合併**：模板只能覆蓋明確允許的設定欄位（預告、B-roll 策略與密度等）；若試圖
  設定配樂、目標解析度或檢索融合參數，會被忽略並警告
- **刻意不模板化的東西**：音樂節奏、ASR 校正、片長預設。規劃時就判斷這三類「依類型套預設」
  容易有反效果——片長該由內容決定、校正該由世界知識決定，都不該被類型綁死
- **B-roll 策略必須設為自訂**：若模板填了預設策略名稱，該策略會強制覆蓋模板自己寫的密度
  數值，模板設定形同虛設。這是寫在模板契約文件裡的已知陷阱
- **「素材不符時」是必填段落**：每個模板都要寫清楚什麼情況下該退回通用結構，並要求在規劃
  文件中記錄模板適配判定（完全適用 / 部分適用 / 不適用）與理由
- **不要硬套**：探店模板明訂「若逐字稿沒有實際試吃與口味評價，退用通用結構，不要把沒有
  第一口反應的素材硬包裝成探店」

### 模板缺口的發現
有兩支片都是「沿著一條街走、逐家介紹店面、回憶推薦吃過的店」——全程沒有在鏡頭前吃東西。
探店模板不適用（沒有試吃）、場所導覽不適用（那是單一場所內的導覽）、旅遊也不適用（沒有
交通與抵達）。

兩次都誠實走通用結構，並把該有的骨架記下來：街道定位開場 → 沿動線逐家一個段落（店名 →
推薦與否 → 具體理由）→ 誠實補充沒吃過的店 → 收尾。這類片的**黃金鏡頭是店面招牌，不是上菜**。
一個實例是偶然，兩個實例就值得補一個模板。
